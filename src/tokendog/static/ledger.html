Read Σ is context summed across every turn in range — a stateless model re-reads the whole window each turn, so it is roughly turns × context, NOT the size of the context (that's Peak). Burn is Read Σ per minute (marked ~ when only a minute or two of activity makes it provisional). Ctx now is the context still live — clearing or compacting starts a fresh one inside the same file, and one transcript here has held eleven. Ctx in window is avg/peak across every context the session held inside the selected range: what it cost here, rather than what it is now. Click a session id for its turn-by-turn breakdown — what entered the window at each turn and what that addition then cost. The json badge beside it returns the same drilldown as data, for handing to something that will analyse it. On the command line: tokendog session <id>, plus --json. Open for is wall-clock from a session's first turn to its last; Idle is time since its last turn. Rows marked headless are non-interactive runs whose processes have exited — nothing is left to close, so their fix belongs to whatever spawns them.

The escalation

There are no dollar figures here, by design. Every number is a token count taken from the per-turn usage the runtime records in its own transcripts — the same counts that were metered. On a subscription there is no per-token charge, and these are not a rate-limit proxy either: quota accounting does not apply the price weights that make output 5× input and a cache read 0.1×. Read them as relative weight, which is all that is needed to see where a window went.

Occupancy is what a turn had to be given — cache read plus cache write plus fresh input. Output is excluded: it came back, it was not carried. Roll-ups key on transcript rather than session id, because a resumed session and its subagent transcripts share one id while each holds a context that grew on its own.
